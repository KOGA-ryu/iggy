# Vulkan Manual And Source Map

This is not a random reading list. Each source below maps to local renderer subsystems and roadmap phases.

## Authority Ranking

1. Source of truth: Vulkan Specification and Registry for exact API behavior.
2. Learning path: Khronos Vulkan Tutorial and Vulkan Guide.
3. Production examples: Vulkan Samples and Building a Simple Engine.
4. Validation/debugging: Validation Overview, Synchronization Validation, RenderDoc.
5. Memory: Vulkan Memory Allocator.
6. Apple portability: LunarG macOS SDK and MoltenVK. MoltenVK explains Apple constraints and exceptions; it is not the cross-platform source of truth.
7. Secondary practical references: modern implementation walkthroughs may inform packet details, but they never override official Vulkan, LunarG, MoltenVK, VMA, CMake, or project boundary docs.

## Shader Toolchain Decision

The shader authoring path is unresolved by design.

Recommendation: keep the first renderer plans shader-language-neutral until Phase 7. At that point use Slang if the macOS SDK path, non-Apple Vulkan path, build scripts, and generated SPIR-V outputs are reproducible. Use GLSL plus glslang if the first-room milestone needs a smaller dependency surface.

The non-negotiable policy is that the renderer consumes SPIR-V artifacts through a documented build step. Runtime, content, projection, and save code must never know which shader language produced those artifacts.

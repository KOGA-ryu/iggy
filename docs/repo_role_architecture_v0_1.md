# iggy3d Repo Role Architecture v0.1

**Ten architectural roles, one-way tower.** A refinement of the 15-kernel down-layer (`docs/kernel_architecture_v0_1.md`) plus the `architecture.md` doctrine (runtime owns truth; apps only call APIs; projection is read-only; save persists; replay proves). This is a **target map, not a move order** — Codex is live-refactoring the shared tree, so files stay put; the map assigns every symbol its role, laws, allowed dependencies, and target home.

**The through-line:** *leverage lives in the readers.* One Descriptor row per kind (Registry) is read by six downstream engines (Kernel), so a new object KIND touches the Registry **once** and nothing else forks. The Pipeline is the composition spine (doc -> room -> graph -> intel -> page); the Facade is the only public surface; the Receipt is the proof that flows up.

---

## The layering (allowed-call direction)

```
apps  -->  [10] Facade  -->  { [8] Pipeline, [3] Dispatcher, [4] Projector, [6] Codec, [5] Validator, [2] Kernel, [7] Index }
[8] Pipeline  -->  [2] Kernel, [5] Validator, [6] Codec        (sequences + gates on receipts)
[3] Dispatcher --> [2] Kernel, [7] Index, [1] Registry          (builds requests; never mutates)
[4] Projector  --> [7] Index, [1] Registry, (Facade getters)    (read-only views)
[5] Validator  --> [7] Index, [1] Registry, [2] Kernel(types)   (checks -> repair-hint; zero mutation)
[6] Codec      --> [2] Kernel, [1] Registry                     (state <-> durable/hash)
[7] Index      --> [1] Registry, [2] Kernel(bounds)             (rebuildable accelerations)
[2] Kernel     --> [1] Registry ; emits [9] Receipt             (the pure engines)
[1] Registry   --> (enums + std lib only)                       (the floor)
[9] Receipt  = leaf value; flows UP as inert data; calls no one
```

**Hard rules:** an arrow never points up. Registry imports nothing from other roles — a per-kind `if` above Registry is a bug that should become a Registry column. Kernel never reads input/routes/renders/serializes. Dispatcher never edits the document. Projector/Validator/Codec/Index mutate nothing. Pipeline holds no domain math. Facade is the only role apps touch. Receipt is the only thing that "moves up," and it moves as data, not a call.

## The 10-role catalog

### 1. Registry — the constexpr read-tables
- **Charter:** the pure compile-time lookup tables answering "what is this kind / command / mutation?" — object facts, command facts, mutation facts. No runtime state, no document, no mutation. The single source of generic per-kind truth every other role reads instead of hardcoding branches.
- **Members (HAS):** `CreativeObjectDescriptor` + capability-flag table + `describeObject/allObjectDescriptors/categoryOf/profileOf/shapeKindForObject` and the pure predicate fan-out (`objectHasTransform/HasBounds/CanHaveParent/...`) — all read the one table (`ObjectDescriptor.*`). The mutation fact-tables `kCreativeMutationMetadataRows` + `categoryOf/isTransformMutation/canMutate/toString(category)` (`Mutation.*`). The UI command rows `kProductCreativeUiCommandCatalog`/`...Palette`/`...KindMetadata` + finders (`UiCommandCatalog.hpp`). `CommandKind/Source/RejectionReason` enums + trait predicates `requiresActor/requiresEntityTarget/...` (`Command.hpp`).
- **Members (NEEDS/WANTS):** the scattered `toString(enum)` name functions belong here as one enum-name registry but aren't collected. The map-affordance wire-string vocabulary (the ONE live cross-lane seam break, facts half) has no Registry row yet.
- **Laws:** MAY be constexpr/header-only, expose value/const-ref lookups keyed by an enum, be included by every role. MUST NOT hold mutable state / a Document / an index; allocate; do I/O; import from any higher role; or branch per-kind outside its own table.
- **Target home:** `iggy3d::registry` — `creative/registry/{ObjectFacts,MutationFacts,CommandCatalog,AffordanceFacts}.hpp`, `runtime/command/CommandFacts.hpp`.
- **May call:** *(none — the floor)*.
- **Gaps (slice):** (1) affordance/wire-string facts table missing — the Pipeline's recon step needs a generic source. (2) toString(enum) not consolidated. (3) no mutation<->command cross-table (Dispatcher hardcodes it today).
- **Boundary:** vs Kernel — Registry answers "what may this kind do" (pure lookup); Kernel answers "do it." The smell: `Mutation.cpp` mixes Registry fact-tables with Kernel variant-dispatch/apply glue in one file; split along the state-free line. vs Receipt — Registry supplies stable *names* (receiptName column); Receipt owns the emitted proof struct.

### 2. Kernel — the pure engines
- **Charter:** create/move/resize/rotate/delete/bake + the (to-be-built) pre-bake validator. Each is generic and deterministic, mutates only the CreativeDocument handed in (bake/validate read-only), and emits a typed receipt. A new object KIND touches these engines **zero** times — legality/effect are read from the Descriptor row, never switched on kind.
- **Members (HAS):** `applyMutation`/per-verb `apply*Mutation` (`MutationApply.*`, purity law in its doc comment). `applyDocumentMutation` + batch + convenience wrappers (`DocumentMutation.hpp`) — the sole edit seam, owns revision-bump-on-real-change, returns `CreativeDocumentMutationReceipt`. `createObject`/`removeDocumentObject` (methods on `CreativeDocument` — the honest wart: coupled to storage while move/resize are free functions). `buildRoomAssetFromCreativeDocument` (`RoomBake.*`) — pure descriptor-driven fold to RoomAsset + `CreativeRoomBakeReceipt`; shared predicate `validBakeBounds`.
- **Members (NEEDS/WANTS):** `validateDocumentPreBake -> CreativeValidationReceipt` does not exist; must delegate to `validateCreativeObjectParentGraph` and reuse `validBakeBounds`, emit `suggestedRepair` as data, apply nothing. Bake's two PARTIAL legs (traversal-link emission, rotation-honoring geometry) are cut sockets inside the engine.
- **Laws:** MAY mutate the single document handed in; read the Descriptor table for legality/effect; return a typed receipt; bump revision only on real change. MUST NOT switch on KIND; touch session/RNG/Date/renderer/codec/UI/tools; APPLY a repair from the validator; read the live scene; or reach up. Bake/validate strictly pure. Determinism is a hard invariant.
- **Target home:** `iggy3d::creative` — verb engines under `creative/mutation/` (create/delete promoted out of Document), bake at `creative/adapters/RoomBake.*`, new validator at `creative/validation/ValidateDocument.*`.
- **May call:** Registry, Receipt.
- **Gaps (slice):** validateDocumentPreBake + its receipt types absent; create/delete inconsistent with the verb family; bake's traversal-link leg falls through to SkipUnsupportedShape (the live cross-lane seam break) and rotation is UNREAD.
- **Boundary:** vs Registry — Registry HOLDS the facts, Kernel READS then writes. vs Dispatcher — Dispatcher decides WHICH verb and builds the request; Kernel only EXECUTES. vs Validator — the Validator judges + emits hints (zero mutation); the Kernel is where a mutation is applied; `validateDocumentPreBake` is the Kernel-family "validate" verb but must stay zero-mutation.

### 3. Dispatcher — input -> intent/command
- **Charter:** turns raw device/UI input into typed, kernel-bound intents and command records; runs the Begin/Preview/Commit/Cancel lifecycle; admits/rejects commands — but never edits the document. The router between the outside world (mouse/keyboard/UI + AI/Script/Replay sources) and the Kernel.
- **Members (HAS):** `dispatchToolInput` (`Tools.*`) — THE canonical pure input->intent router; `CreativeToolIntentKind` (Begin/Preview/Commit/Cancel + Move variants), intent lists, dispatch receipt. `applySelectionToolIntent` (`Select.*`, tool-local state only), `applyMeasurementToolIntent` (`Measure.*`), `buildPlacedCreateRequest` (`Placement.*`, returns a request — textbook dispatcher output). Palette/RoomShell tool state. `CommandRecord`/`CommandKind`/`CommandSource` + `admitCommand`/`acceptCommand`/`rejectCommand` (`Command.hpp`/`CommandAdmission.*`). `routeProductCreativeUiCommandFrame` (`UiCommandFrame.*`). `processProductWindowInputFrame` (`window/InputFrame.*`).
- **Members (NEEDS/WANTS):** a unified CommandRecord/admitCommand path for creative authoring edits (`CommandSource::Tool` exists but creative dispatch bypasses it); a single lifecycle owner for Begin/Preview/Commit across move-drag + place + measure. WANTS: Replay/Script ingestion sharing the same admit gate.
- **Laws:** MAY read Registry facts + current state to resolve input to an intent/request; build typed intents/requests/CommandRecords; run the lifecycle + hold transient tool-local state; admit/reject; emit a dispatch receipt. MUST NOT mutate the document/WorldState; run validation/repair; serialize; render/pick pixels as an end; or reach up.
- **Target home:** `creative/tools/` + `runtime/command/` under `iggy3d::*::dispatch`; `window/InputFrame.*` + bridge input frames are the front porch. The intent-routing body inside `Facade::dispatchToolInput` migrates down into `tools/`.
- **May call:** Registry, Kernel, Index.
- **Gaps (slice):** (1) creative edits don't flow through a unified admitCommand path. (2) three parallel Begin/Preview/Commit lifecycles (move-drag in Facade, measure in Measure, two-step place in Placement). (3) no shared dispatcher seam for AI/Script/Replay into creative.
- **Boundary:** vs Kernel — Dispatcher DECIDES + builds the request; Kernel EXECUTES (tell: `buildPlacedCreateRequest` returns a request; tool appliers mutate only tool-LOCAL state). vs Projector — screen->world picking is READ-ONLY view math (Projector); the Dispatcher consumes the resolved world point. Rule: changes the document = Kernel; computes a pixel/ray = Projector; "do X to the engine" without doing X = Dispatcher.

### 4. Projector — read-only views
- **Charter:** every pure read-only view derived from authoritative state: UI draw-lists, screen-picking geometry, grid/gizmo overlays, the notebook recon page, the reasoning-graph summary, the guard-recon observation. Takes state + camera/viewport, returns a derived artifact + receipt; never owns truth, never mutates.
- **Members (HAS):** `buildProductCreativeUiProjection` (`UiProjection.*`, the exemplar) + `CreativeUiModel`/`UiFrame`/`UiDrawList`. `projectBoxToScreen/projectPointToScreen/worldRayFromPixel/clipW/pointToSegmentDistancePx` + `pickPathPointHandle/pickGizmoAxisFromProjectedShafts` (`StandalonePicking.*` — read-only hit-tests over projected geometry). `summarizeReasoningGraph` (`ReasoningGraph.*`). `buildProductNotebookUiDrawList` (`Notebook.*`).
- **Members (NEEDS/WANTS):** `projectGuardRecon` (ABSENT) — pure read over durable AiActorState; the one missing datum is `alertBandName` (0..5 band label). Grid/gizmo overlay projection is INLINE in `main.cpp` — needs extraction into a named read-only overlay projector. WANTS: the notebook page is still filled by the test fixture `sampleReconPage`; Projector holds only the RENDER, the fill is Pipeline's.
- **Laws:** MAY read authoritative state via const refs / Facade getters; take camera+viewport as inputs; compute clip/screen/summary/observation artifacts; emit a receipt; degrade gracefully. MUST NOT mutate/own truth; call the mutation path; apply a repair; touch undo rings/dirty channels/codec; read RNG/Date; or fabricate facts (a projected node-id must be a real coincidence). Deterministic: headless pixel tests pin `projectBoxToScreen` exactly.
- **Target home:** creative UI views in `creative/ui/`; screen-picking math LIFTED from the app binary into `creative/spatial/ScreenProjection.*`; notebook view in `menu/`; reasoning summary + `projectGuardRecon` beside `ReasoningGraph` in `runtime/ai/`; grid/gizmo overlay extracted from `main.cpp`.
- **May call:** Registry, Index, Facade.
- **Gaps (slice):** `projectGuardRecon` (head of the chain) unbuilt but UNBLOCKED except `alertBandName`; grid/gizmo overlay inline; screen-picking trapped in the app binary; notebook rendered from a fixture until `captureReconIntel` lands.
- **Boundary:** vs Dispatcher — Projector answers "does this pixel land on object 7?"; Dispatcher answers "so select 7." vs Pipeline — Projector RENDERS a page; Pipeline PRODUCES it (`captureReconIntel`); Projector never aggregates/hashes intel. vs Kernel — `buildAuthoringHandles` ENUMERATES (engine); `pickPathPointHandle` READ-tests against the result (view query).

### 5. Validator — the pre-bake conscience
- **Charter:** one pure pass that reads a CreativeDocument (+ Descriptor legality + Spatial reachability) and emits repairable diagnostics as DATA — validate -> repair-hint -> receipt, ZERO mutation. Answers "is this safe to bake/persist, and if not, exactly what mutation would fix it?" but hands a `suggestedRepair` (a CreativeMutationRequest) to the caller; the Kernel owns the edit.
- **Members (HAS):** `validateCreativeObjectParentGraph` (`Document.cpp`, pure reason-code, wired into DocumentMutation + restore) + its helpers. `validBakeBounds`/`validAnchorPosition` (`RoomBake.cpp`, pure finite/fits checks — Validator predicates stranded in Bake). The AsciiRoom `diagnostic()` (the diagnostics-as-data exemplar). Shared `core/diagnostics/Diagnostic.hpp`.
- **Members (NEEDS/WANTS):** `validateDocumentPreBake -> CreativeValidationReceipt{passed, reasonCode, diagnostics[], counts}` composing parent-graph (HAS) + bounds/anchor finiteness (HAS-but-embedded) + reachability (NEEDS peer `floodFillReachability`); `CreativeValidationDiagnostic` carrying `suggestedRepair` as inert data. WANTS: unify bake's `Skip*` reasons so they become downstream consequences of a validation diagnostic.
- **Laws:** MAY read the document/objects/Descriptor rows + Spatial results; call legality predicates + Index queries; emit typed diagnostics + `suggestedRepair` as inert data; return a stable receipt. MUST NOT mutate; apply its own repair; touch codec/renderer; branch per-kind; or reach up. Pure and deterministic.
- **Target home:** `creative/validation/` (`creative::validation`); `validateCreativeObjectParentGraph` migrates here (thin call-through until the tree quiets); bounds/anchor predicates become shared Validator predicates that RoomBake calls INTO.
- **May call:** Registry, Index, Kernel.
- **Gaps (slice):** the unified pass, the diagnostic/receipt types, and the `suggestedRepair` field don't exist; `floodFillReachability` unwired; `validBakeBounds` trapped in Bake (computed twice); no Validator receipt in the test surface (the validate->REPAIR->receipt DNA is unproven for the creative document).
- **Boundary:** vs Kernel — Validator READS + JUDGES + suggests; Kernel WRITES. Bake does both today (`validBakeBounds` + enforce skip) — the stranded predicate is the tell. vs Receipt — Receipt owns the proof types generally; Validator is one PRODUCER that emits a `CreativeValidationReceipt`.

### 6. Codec — state <-> durable/comparable
- **Charter:** converts live state into a durable or comparable form and back — serialize/deserialize (save/load), hash (stable fingerprint for equality + replay proof), snapshot/restore (in-memory rewind). Three seams: HASH, CODEC, RESTORE — always emitting a typed status/receipt on the way back in.
- **Members (HAS):** `StableHasher` FNV-1a + `computeStateHash`/`formatStateHash` (`StableHash.*`/`StateHash.*`) — HASH. `encodeSaveEnvelope`/`decodeSaveEnvelope` + `SaveCodecStatus` (12 codes) + `SaveEnvelope`/`Save*Section` schema + `SaveCompatibility` (`runtime/save/`) — CODEC. `buildSaveCreativeDocumentSection`/`restoreCreativeDocumentFromSaveSection` (`DocumentSection.*`) — RESTORE. `CreativeDocumentUndoStack` + `pushCreativeUndoSnapshot`/`applyLastCreativeUndoSnapshot` (`CreativeAppState.hpp`) — SNAPSHOT-RING. Reads `id()/revision()/nextObjectId()` to stamp/verify (does not own id allocation).
- **Members (NEEDS/WANTS):** `SaveFileStore`/`SaveLoad` mix pure codec with filesystem IO — pure encode/decode is Codec, file-effect layers above. WANTS: a redo ring (zero `redo` symbols in creative — the undo stack is one-way).
- **Laws:** MAY read any state to serialize/hash/snapshot; produce bytes/u64/document-copy; emit a typed status. MUST be deterministic (quantize floats, never hash raw bits/pointers), version-aware (refuse UnsupportedVersion), round-trip, and hand the decoded candidate to the Validator BEFORE install. MUST NOT mutate live truth (restore returns a NEW document); embed policy/per-kind branching; reach up; or do file/network IO inside the pure core.
- **Target home:** `iggy3d::codec` — `codec/{hash,save,restore,snapshot}`; the snapshot ring migrates down from the app layer; file-IO stays a thin wrapper above the pure codec.
- **May call:** Registry, Kernel.
- **Gaps (slice):** (1) REDO ring missing — the slice's rewind is irreversible. (2) reasoning-graph + recon-intel have NO save section. (3) `SaveCodec.cpp` is 1971 lines of hand-rolled line parsing (no table-driven codec). (4) `computeStateHash` covers SessionState only — the CreativeDocument snapshot ring has no stable-hash equality.
- **Boundary:** vs Validator — Codec answers "is this well-FORMED?" (structural/syntactic status); it does NOT decide "is this LEGAL/coherent?" (Validator, run AFTER decode, BEFORE install). `DocumentSection` straddles this (InvalidDocumentId = structural vs Converted = repair outcome); clean split = candidate+structural status, then Validator repairs. vs Persistence-Kernel — Codec READS identity/revision to stamp; id/revision ALLOCATION policy is Kernel/Registry.

### 7. Index — measured accelerations
- **Charter:** fast lookup structures that accelerate access into document/world state — id-to-object, world-to-grid occupancy, and (deferred) AABB broadphase. Indexes are rebuildable accelerations of Registry/Kernel truth; they hold NO authoritative data. Deferred by law: created only under measured pressure.
- **Members (HAS):** `Document::objectIndex_` — the id-to-row hash map, maintained incrementally by mutation paths (cleared/inserted/swap-erased/move-restored/read); complete and live; the role owns its contract but must NOT reimplement it. `projectObjectsToGrid` + per-shape projectors + grid math + `CreativeSpatialCell` + `occupancyKindForObject` (`SpatialProjection.*`) — the world-to-grid occupancy spine. `pickCreativeViewportCell` (`ViewportPick.*`) — an occupancy query verb.
- **Members (NEEDS/WANTS):** occupancy is NOT cached — `projectObjectsToGrid` is rebuilt every viewport-pick frame (`ViewportPickFrame.cpp`) and again for wireframe (`DocumentWireframe.cpp`), two readers each paying O(N). WANTS: `CreativeObjectAABBIndex` — a coarse hash-grid over AABBs + 4 query verbs (copy `collectPhysicsBroadphasePairs`, ~80% exists); a reserved socket only.
- **Laws:** MAY build/rebuild purely from Registry facts + Kernel bounds; expose read-only query verbs returning id-sorted/cell candidate sets; carry receipt-style counters. MUST NOT mutate; be treated as authoritative; invent an index before measured pressure; reach up; or run exact narrowphase (return candidates; caller does the precise test). Query output stable/id-sorted for replay.
- **Target home:** `iggy3d::creative` — `creative/spatial/` for occupancy + pick + the future `AABBIndex`; the id index stays a private member of Document (Index only names its contract). Precedent: `runtime/physics/PhysicsBroadphase.*`.
- **May call:** Registry, Kernel.
- **Gaps (slice):** nothing strictly required — id index + occupancy already power pick/select/bake at current counts. The one real gap is caching (two readers rebuild O(N) with zero reuse — the activation trigger, not yet the activation). `CreativeObjectAABBIndex` fires only at ~100+ objects or a second all-object query verb; building it before a measured off-frame scan violates defer-until-measured.
- **Boundary:** vs Projector — Projector renders read-only VIEWS for humans; Index builds read-only LOOKUP structures for the engine (tell: ViewportPick answers "which object is here?" for a command to act on = Index; drawing/highlighting = Projector). vs Registry — Registry holds authoritative tables; Index holds a rebuildable acceleration; if they disagree, Registry wins and the index rebuilds.

### 8. Pipeline — the composition spine
- **Charter:** the composition chain that orchestrates Kernels in sequence — creative doc -> room asset -> reasoning graph -> recon intel -> notebook page — and OWNS the sequencing + graceful-degradation gates between stages. Each stage is a pure Kernel; the Pipeline is the thin deterministic wiring that runs them in order, threads one stage's typed output into the next's typed input, and decides (via receipt inspection) proceed/degrade/stop. It holds no domain math of its own.
- **Members (HAS, informal today):** `buildStandaloneRoomBakePreviewScene` (`StandaloneRoomBakePreview.cpp`) — the clearest existing pipeline: bake -> scene projection -> augmentation with an empty-mesh degradation gate. `ProductCreativeBakedActiveRoomRefresh::execute()` (`Operations.cpp`) — the production chain: preconditions gate -> bakeDocument -> mirrorBakeResult -> receipt gate (-> handleRejectedBake with a no-renderable degradation branch) -> installBakedRoom. Pipeline logic inlined in app files.
- **Stages it sequences (owned by Kernel/Validator):** Stage 0 Validate `validateDocumentPreBake` (NEEDS); Stage 1 Bake `buildRoomAssetFromCreativeDocument` (HAS); Stage 2 Reasoning-graph `buildReasoningGraph` (engine HAS, but the doc->room->GRAPH link is BROKEN — `Session::setReasoningGraph` has NO production caller, only tests fill it; downstream readers are live); Stage 3 `projectGuardRecon` (NEEDS); Stage 4 `captureReconIntel`/`serializeReconIntel` (NEEDS); Stage 5 `buildNotebookReconPage` (WANTS — the ReconIntel notebook packet does not exist anywhere in src).
- **Laws:** MAY call Kernels/Validator in a fixed deterministic order; read each stage's receipt to branch (proceed/degrade/halt); thread output->input; own degradation gates (no-renderable -> clear-room; empty graph -> skip recon, not crash); return a composite receipt. MUST NOT contain domain math; mutate the document; touch RNG/Date/session-global inside the chain; reach up; or skip the pre-bake Validator gate once it exists. Each stage boundary is a receipt checkpoint.
- **Target home:** a new `iggy3d::creative::pipeline` at `creative/pipeline/` (no such dir today). Sits ABOVE the creative/runtime seam; reachable only through the Facade. The two inline pipelines are the extraction sources; the reasoning-graph fill arrow lands as a room-load hook calling `Session::setReasoningGraph`.
- **May call:** Kernel (per-stage engines), Validator (pre-bake gate), Receipt (reads each stage's receipt, emits a composite), Registry (read-only facts), Codec (Stage 4 serialize + the reserved SaveReconIntelSection).
- **Gaps (slice):** the entire back half is missing — (1) THE #1 BLOCKER: nothing calls `Session::setReasoningGraph` in production (the single missing fill arrow); (2) `projectGuardRecon` + `alertBandName`; (3) `captureReconIntel`/`serializeReconIntel` + the ReconIntel packet type; (4) `buildNotebookReconPage`; (5) `validateDocumentPreBake`; (6) no Pipeline HOME — the two chains are inlined and stop at bake->install; nothing sequences past room into graph/intel/page.
- **Boundary:** vs Kernel — a Kernel is ONE pure engine knowing nothing before/after it; the Pipeline knows the ORDER + GATES. A Kernel that calls the next Kernel is a mis-scoped Pipeline; a Pipeline that computes geometry is a mis-scoped Kernel. vs Facade — the Facade is the flat public surface (one call -> one result); the Pipeline is the internal multi-stage machine BEHIND a Facade entry. vs Dispatcher — the Dispatcher routes a single input->one kernel edit; the Pipeline runs a settled document through a read-only multi-kernel derivation and mutates nothing.

### 9. Receipt — the typed proof
- **Charter:** the typed proof-of-work value every Kernel/Validator/Pipeline/Codec stage returns alongside its effect — a plain data record naming WHAT happened, WHY (reasonCode), and WITH WHAT COUNTS/DIAGNOSTICS, so tests pin behavior against a stable observable contract, not mutated internal state. The "report" tail of source->generation->validation->decision->report, and the surface the Projector renders into human-readable form.
- **Members (HAS):** `CreativeDocumentMutationReceipt`/`...BatchMutationReceipt` (`DocumentMutation.hpp`). `CreativeRoomBakeReceipt`/`...Result` (`RoomBake.hpp`, the validate->emit exemplar; the conservation invariant considered == baked + sum-of-skips lives here). `GuardDecisionReceipt`/`GuardDecisionFactor` (`GuardDecisionReceipt.hpp`, a light header split so it rides IN durable AiActorState). `CreativeSpatialProjectionReceipt`. `ReasoningGraphSummary`. `RuntimeSummary`/`CommandReplayReport` ("replay proves" as data). `ProductMovementProofPacket` (`MovementProof.hpp`). `AsciiRoomDiagnostic` (the precedent the validation receipt copies).
- **Members (NEEDS/WANTS):** `CreativeValidationReceipt`/`CreativeValidationDiagnostic{suggestedRepair}`; `ReachabilityReceipt`; `GuardReconObservation`; `ReconIntel` (+ hash/serialize form — the packet that "does not exist in src," the #1 structural gap; today only the Projector-side `ProductNotebookReconPage` + fixture `sampleReconPage` exist). WANTS: NavReceipt, VisibilityReceipt, AABBIndex degenerateBoundsCount.
- **WATCH (NOT a typed receipt):** `ReceiptBuilder.{hpp,cpp}` (861 lines of Product*Diagnostics + text-formatting) is a **Projector** concern (formatting proofs into HUD/debug strings), not the pure typed receipts.
- **Laws:** MAY be a pure POD-like aggregate; carry a status enum + reasonCode + message + counts + per-kind arrays + signed factors; be embedded in durable state or returned by value; be compared field-by-field or by stable hash; carry `suggestedRepair` as inert data. MUST NOT contain mutating logic; reach up; own RNG/Date/IO; APPLY a repair; depend on renderer/codec internals; or be per-kind. A receipt is DESCRIBED BY lower layers and READ BY upper layers — it never calls anyone.
- **Target home:** LEAF value types co-located with the emitting kernel (in that kernel's public header). No single receipt/ dir — the pattern is "light header beside the kernel," exemplified by `GuardDecisionReceipt.hpp`. Shared primitives (status enums, DiagnosticLocation) in `core/diagnostics/Diagnostic.hpp`.
- **May call:** Registry.
- **Gaps (slice):** four receipt TYPES missing — `CreativeValidationReceipt`+diagnostic, `ReachabilityReceipt`, `GuardReconObservation`, `ReconIntel` (the packet). Secondary: no shared invariant-assertion helper for the conservation law; bake receipt has no rotation-honored / link-emitted counters.
- **Boundary:** vs Projector — a Receipt is the TYPED, machine-comparable proof struct; `ReceiptBuilder` FORMATS those proofs into HUD/debug TEXT (same word, opposite side of the read boundary). Rule: if a test asserts equality on it, it's a Receipt; if it produces a string for a screen, it's a Projector view. The Product*Diagnostics structs are a gray zone owned by the Projector — they should NOT migrate into Receipt. vs Validator — the Validator is the ENGINE that runs checks + emits `suggestedRepair`; the Receipt is the inert value it CARRIES and never applies.

### 10. Facade — the single public seam
- **Charter:** the single safe public seam apps touch to drive the creative editor. Owns the live editor state (document + tool + selection + measurement + snap + ghost + move-drag), routes app requests into Kernel/Dispatcher, and returns a typed Receipt for every call. Nothing above it may reach past it into Registry/Kernel/Document directly.
- **Members (HAS, `Facade.hpp/.cpp`, 912 lines):** `class Facade` held via `CreativeAppState.facade`. Lifecycle `reset/beginFrame/handle`. Const read accessors delegating to state. Command entry points each returning a receipt: `setActiveTool`, `setSnapSettings`, `dispatchToolInput`, `toggleSelectedObjectVisibility/Locked`, `createDocumentObject`, `removeDocumentObject`, `installDocument` (the sole validated whole-document swap), `createDocumentObjectsAtomically`, `buildUiModel`. Facade-owned receipt/status types (logically Receipt-role, defined at the emitting seam). Private orchestration helpers (`applyMoveDragIntent`, `snapWorldAnchor`, `holdMoveAxis`, ...) that turn a raw input packet into a snapped, held-axis Move payload before calling the Kernel.
- **Members (NEEDS — leaks to seal):** `documentForPersistence()` returns a MUTABLE `CreativeDocument&` — the escape hatch `StandalonePathEditing.cpp` uses to call `applyDocumentMutation` on the raw document (bypassing the receipt seam); NEEDS a real Facade path-edit command so the handle narrows to a Codec-only const drain. Apps also `#include` creative internals directly (`DocumentMutation.hpp`/`Mutation.hpp`/`RoomBake.hpp` are true bypasses).

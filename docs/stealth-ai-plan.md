# iggy3d Stealth Perception + Alert System — Phased Implementation Plan

Clean-room design derived from The Dark Mod (GPL) **as reference values and state-machine shape only**. No TDM code is transcribed. All work lives in `src/runtime/ai/` and `src/runtime/physics/` (read-only reuse of physics). Every slice is a set of free functions over plain structs, deterministic, headless-unit-testable, and registered as a `*_tests` target in iggy3d's CMake. Per the project's **no-hardcoded-dimensions** rule, every distance/angle/tick threshold is a *named config field*, never an inline literal.

Anchor facts verified against the real source:
- `queryNpcPerception` (`NpcBehaviorSystem.cpp:191`) computes `result.distanceMeters` via `horizontalDistanceMeters` (Y-flattened), then sets `targetInPerceptionRadius`, and short-circuits to `TargetOutOfRange` at line 253 **before** doing any further work — this is our cheap-reject point, the analog of TDM's PVS/range cull.
- `raycastPhysicsAabbs(PhysicsRaycastQueryRequest)` returns `PhysicsRaycastQueryResult{ ok, hits[] }` where each `PhysicsRaycastHit` has `distanceMeters`, `startInside`, `colliderIndex` (`PhysicsCollisionQueries.hpp:46-74`). Request fields: `colliders` (pointer to `vector<PhysicsAabbCollider>`), `originMeters`, `direction`, `maxDistanceMeters`, `includeSensors`.
- `AiActorState` (`AiState.hpp:67`) already carries `nextDecisionTick`, `cooldownTicksRemaining`, `homePosition`, `leashRadiusMeters`, `deterministicPolicy` — we extend it, never replace it.

## SLICE 1 — Line-of-sight occlusion gate *(ship first)*

**Why.** Today perception is radius-only: an NPC "sees" a target through a solid wall. This is the single highest-value, lowest-risk fix and needs **no facing vector**, so it unblocks the whole stealth track. It mirrors TDM's `idActor::CanSee` occlusion trace (`MASK_OPAQUE` ray eye→target), reduced to: *blocked iff any opaque blocker is strictly nearer than the target along the ray*.

**Behavior change.** When `requireLineOfSight` is on and a sight-blocker set is supplied, a target that is inside the perception radius **but occluded** is no longer detected: `targetVisible = targetInPerceptionRadius && lineOfSightClear`. The downstream decision layer keys off `targetVisible` instead of `targetInPerceptionRadius`. With the feature off (or `sightBlockers == nullptr`), behavior is byte-identical to today (full back-compat).

### New / changed structs

`NpcBehaviorConfig` (`NpcBehaviorSystem.hpp:23`) gains — **all named, no magic literals**:
```cpp
float eyeHeightMeters       = 1.6F;   // ray endpoints lifted by this along +Y
bool  requireLineOfSight    = false;  // opt-in; false keeps every existing test green
float lineOfSightEpsilonMeters = 0.01F; // grazing-hit slack at the target wall
```
`eyeHeightMeters` default `1.6` is a humanoid standing eye height — a named field, not a literal at the call site (satisfies the no-hardcoded-dimensions rule).

`NpcPerceptionRequest` (`:51`) gains:
```cpp
const std::vector<PhysicsAabbCollider>* sightBlockers = nullptr; // nullptr => radius-only
```
Use the room's `actorBlocker` bake from `ActiveRoomCollision`/`SpatialSurfaceSet` as the v1 sight-blocker set. (Future: a dedicated `sightBlocker` surface class so glass can be non-occluding — out of scope here.)

`NpcPerceptionResult` (`:59`) gains:
```cpp
bool  targetVisible       = false;  // targetInPerceptionRadius && !lineOfSightBlocked
bool  lineOfSightBlocked  = false;
float lineOfSightDistanceMeters = 0.0F; // 3D eye→eye distance actually traced
```
Optionally add `NpcPerceptionStatus::TargetOccluded` — but **prefer the boolean flag**, keeping `status = Ready` so existing status assertions stay green; the decision layer reads `targetVisible`.

### Exact algorithm (insert after line 256, *after* the radius cheap-reject)

```
if requireLineOfSight && sightBlockers != nullptr:
    Vec3 up = {0,1,0}
    Vec3 eye    = actorPosition  + up * eyeHeightMeters
    Vec3 tgtEye = targetPosition + up * eyeHeightMeters
    Vec3 delta  = tgtEye - eye
    float dist3d = length(delta)                  // NOTE: full 3D, not horizontalDistanceMeters
    lineOfSightDistanceMeters = dist3d
    if dist3d <= eps: targetVisible = true        // coincident; trivially visible
    else:
        req.originMeters = eye
        req.direction    = delta / dist3d
        req.maxDistanceMeters = dist3d
        req.colliders = sightBlockers
        req.includeSensors = false
        res = raycastPhysicsAabbs(req)
        occluded = res.ok && any hit in res.hits with
                     hit.distanceMeters < (dist3d - lineOfSightEpsilonMeters)
        lineOfSightBlocked = occluded
        targetVisible = !occluded
else:
    targetVisible = true   // degrades to radius-only
```

Critical gotchas baked in:
- **Use 3D length for the LOS ray**, not the existing `horizontalDistanceMeters` — the eye lift makes the segment non-horizontal, and a Y-flattened length would mis-scale the ray.
- **"Nearer than the target" compare, not "hit == target."** In iggy3d the target entity is *not* in the collider set, so we can't use TDM's `hit==target` test. We compare `hit.distanceMeters` to the traced target distance and subtract `lineOfSightEpsilonMeters` so a blocker coincident with the wall *behind* the target doesn't spuriously occlude.
- **Raycast runs only after the radius reject** (line 253 already returns `TargetOutOfRange` first), so out-of-range targets pay zero LOS cost — TDM's cheap-reject-first discipline, for free.
- Ignore `startInside` hits at the eye origin if a blocker straddles the actor's own body — if this surfaces in testing, drop hits with `startInside == true` (a blocker the eye begins inside isn't an occluder of the far target).

### Tests (`tests/npc_perception_los_tests.cpp`)
1. Clear LOS, target in radius → `targetVisible == true`, `lineOfSightBlocked == false`, `status == Ready` (regression vs today).
2. One `actorBlocker` AABB straddling the eye→target segment → `targetVisible == false`, `lineOfSightBlocked == true`, even though `targetInPerceptionRadius == true`.
3. Blocker **behind** the target (farther than `maxDistance`) → not occluding → `targetVisible == true` (proves the nearer-than-target compare).
4. Blocker coincident with the target surface within `lineOfSightEpsilonMeters` → **not** counted (grazing-hit epsilon).
5. Target out of perception radius → short-circuits at line 253, `status == TargetOutOfRange`, no raycast performed.
6. `sightBlockers == nullptr` → radius-only, result identical to pre-slice (back-compat).
7. `requireLineOfSight == false` → radius-only regardless of blockers (opt-in guard).
8. Knee-high blocker intersecting the floor segment but below the eye-line → does **not** occlude (eye-height lift correctness).
9. Determinism: identical request over repeated ticks → byte-identical `NpcPerceptionResult`.

## SLICE 2 — FOV vision cone

**Why.** A guard shouldn't see directly behind itself. TDM's `CheckFOV` is a precomputed cosine-of-half-angle dot test; it runs *before* the occlusion trace as the cheaper gate. **Requires a facing vector, which `AiActorState` lacks today** — that's why it's slice 2, not part of slice 1.

**What.** Add a facing direction to the actor and a free function `fovConeContains(...)`. Gate `targetVisible` additionally on the cone.

### iggy3d structs touched
- `AiActorState`: add `Vec3 facingDirection{0,0,1};` (unit forward; normalized on use). If the engine already derives facing from velocity/transform elsewhere, source it there instead and skip the field.
- `NpcBehaviorConfig`: add
  ```cpp
  float fovHorizontalDegrees = 200.0F; // full cone; 360 disables horizontal gate
  float fovVerticalDegrees   = 120.0F; // full cone; <=0 reuses horizontal
  ```
  Precompute `cosHalfHoriz = cos(fovHorizontalDegrees * 0.5 * pi/180)` etc. inside the free function (or cache on a derived struct).
- `NpcPerceptionResult`: add `bool targetInФov` → fold into `targetVisible = targetInPerceptionRadius && lineOfSightClear && targetInFov`.
- Free function: `bool fovConeContains(eye, forward, upAxis, targetPoint, cosHalfHoriz, cosHalfVert)`.

### Reference thresholds (TDM → iggy3d, re-tuned for a 3rd-person game)
- TDM default `fov` spawnarg = **150°** full horizontal (half-angle 75°, `cos75 ≈ 0.2588`). TDM's `m_fovDotHoriz == 1.0` is the "FOV disabled" sentinel.
- iggy3d guards usually want a **wider** cone (~200°) so they aren't trivially flanked; expose it as data and let the designer tune. Preserve a **disable sentinel** (e.g. `fovHorizontalDegrees >= 360` → cone always passes), the analog of TDM's `1.0`.
- FOV math: dot of forward with the horizontal-projected `(target - eye)`; pass iff `dot >= cosHalfHoriz` **and** vertical-elevation cosine `>= cosHalfVert`. Horizontal cone with optional separate vertical cone.

### Tests
- Target dead ahead → in cone; directly behind → out of cone.
- Target exactly at the half-angle boundary → boundary pass/fail locked by `>=`.
- `fovHorizontalDegrees >= 360` sentinel → cone always passes (omniscient look).
- FOV + LOS interaction: target in cone but occluded → `targetVisible == false`; out of cone but clear LOS → `targetVisible == false`.
- Vertical cone: target far above the eye beyond `fovVerticalDegrees` → out.
- Determinism over repeated ticks.

## SLICE 3 — Light-level / shadow visibility (data light-field proxy)

**Why.** The core stealth fantasy: stand in shadow and a guard with clear LOS still doesn't see you. TDM layers a **soft gate** (light + acuity + distance) *after* the geometric gate. iggy3d has no renderer-side lightgem, so we model light as **plain authored data** — a `LightField` — and reuse the existing raycast for the shadow test. No GPU, no portal/PVS.

**What.** A sampled point-light field + a `lightLevelAt` free function that sums per-light linear falloff (with a raycast shadow test against blockers) into a `0..1` scalar, then a calibration curve into a "visibility fraction" that **shrinks the effective perception radius** in shadow.

### iggy3d structs touched
New plain structs (in a new `src/runtime/ai/LightField.hpp`):
```cpp
struct PointLightSample { Vec3 positionMeters; float radiusMeters; float luminance; bool castsShadow; };
struct LightField { std::vector<PointLightSample> lights; float ambientLuminance = 0.0F; };
```
`NpcPerceptionRequest`: add `const LightField* lightField = nullptr;` (nullptr → light gate off, fully lit).
`NpcPerceptionResult`: add `float targetLightLevel; float targetVisFraction; float effectivePerceptionRadiusMeters;`.
`NpcBehaviorConfig`: add named fields
```cpp
float darknessSightThreshold = 0.1F;   // visFraction below this => unseen
float perceptionLightScale   = 1.0F;   // multiplies effective radius
// (acuity multiplier comes later, via alert state in slice 5)
```
Free functions:
- `float lightLevelAt(Vec3 pos, const LightField&, const std::vector<PhysicsAabbCollider>& shadowBlockers)` — for each light: skip if `dist > radius`; `brightness = luminance * (radius - dist) / radius`; if `castsShadow`, **one** `raycastPhysicsAabbs` from `pos` to the light position against `projectileBlocker`/`actorBlocker` AABBs, drop the light if blocked; accumulate `+= brightness`; **early-out at `>= 1.0`**; add `ambientLuminance`; clamp `[0,1]`; **floor to `2/32` if any light reached** the point.
- `float calibrateVisibility(float level)` — convex curve. **v1: `level*level`** (cheap convex stand-in the learner can read); cite TDM's 5th-order polynomial as the eventual tuning target, *never copy its coefficients*.

### Gate logic (in `queryNpcPerception`, after LOS/FOV)
```
targetLightLevel = lightField ? lightLevelAt(targetPosition, *lightField, *sightBlockers) : 1.0
visFraction = calibrateVisibility(targetLightLevel)          // * acuity once slice 5 lands
targetVisFraction = visFraction
effectiveRadius = perceptionRadiusMeters * visFraction * perceptionLightScale
effectivePerceptionRadiusMeters = effectiveRadius
require visFraction >= darknessSightThreshold AND distanceMeters <= effectiveRadius
```
Couple distance to brightness (TDM's `clampdist = sightmin * visFraction`): a dim target is noticed only at short range. Two compounding effects from one scalar — replicate that, don't decouple.

### Reference thresholds
- Darkness threshold **0.1** (visFraction below → hidden), gem band 1..32, floor **2/32 = 0.03125**, sight distances **15 m / 40 m** (`sightMin`/`sightMax`) as the radius-coupling tuning seeds.
- Per-light falloff `luminance * (radius - dist) / radius`; luminance from RGB via **Rec.601 0.299/0.587/0.114** (a documented constant, safe to reuse — the *coefficients* that are TDM-specific are the calibration polynomial's, not Rec.601).
- The shadow test inside `lightLevelAt` is occlusion of the **light** (point→light ray), distinct from the AI's view of the target. Keep them orthogonal.

### Tests
- `lightLevelAt`: single light at center → `~luminance` (clamped 1.0); at radius → 0; at half-radius → `~0.5*luminance` (linear falloff).
- Two overlapping lights sum and clamp at 1.0.
- `castsShadow` light with a blocker between point and light → contributes 0; other lights still count (exercises the raycast reuse).
- Floor rule: one weak distant light with contribution `< 1/32` still yields `2/32`, not 0.
- Gate: target in full light within radius → visible; same target in darkness (visFraction below `0.1`) → not visible despite clear LOS.
- Effective-radius coupling: target at 5 m, visFraction 0.3, radius 6 m → effective 1.8 m → not perceived; move to 1.5 m → perceived.
- `lightField == nullptr` → fully lit, identical to slice-2 behavior (back-compat).
- Determinism.

## SLICE 4 — Sound / hearing stimulus

**Why.** Stealth needs ears: a footstep or dropped object out of sight should *raise alert* and seed an investigate spot, even beyond the visual perception radius. TDM models this through a BSP portal wavefront — **which does not port** (iggy3d has no portals). We collapse it to a single straight-line dB falloff plus one optional blocker check via the existing raycast.

**What.** A transient `SoundEvent` stimulus + pure audibility functions producing alert units and an investigate position. This does **not** replace radius perception; it augments it (wakes Idle→Alert beyond the visual radius and supplies a Vec3 to investigate).

### iggy3d structs touched
New plain structs:
```cpp
struct SoundEvent { EntityId source; Vec3 originMeters; float loudnessDb; float alertFactor = 1.0F; float alertMax = 30.0F; };
struct SoundPerceptionConfig { float hearingThresholdDb = 20.0F; float falloffCoeff = 9.0F; float perWallLossDb = 20.0F; float airLossDbPerMeter = 0.0F; };
struct SoundPerceptionResult { bool heard = false; float audibilityDb = 0.0F; float alertUnits = 0.0F; Vec3 investigatePos; };
```
Put `SoundPerceptionConfig` either on `NpcBehaviorConfig` or as a sibling referenced by `behaviorProfileId`.

Free functions (pure):
- `float soundAudibilityDb(const SoundEvent&, Vec3 listenerPos, const SoundPerceptionConfig&, bool blockerBetween)`:
  `dist = length(origin - listener); base = loudnessDb - (falloffCoeff*log10(max(dist,1.0)) + airLossDbPerMeter*dist); if blockerBetween: base -= perWallLossDb; return base;`
- `bool hearsSound(audibilityDb, hearingThresholdDb) => audibilityDb > threshold`
- `float soundToAlertUnits(audibilityDb, threshold, alertFactor, alertMax) => clamp(1 + (audibilityDb-threshold)*alertFactor, 0, alertMax)`
- `blockerBetween` reuses `raycastPhysicsAabbs` listener→origin against `doorBlocker`/`actorBlocker`; a hit before reaching the origin → apply `perWallLossDb` once. **v1 may skip the ray** (treat as open-air) and still be faithful for open rooms.

### Reference thresholds (TDM, dB, **all losses positive**)
- Hearing floor **20 dB**; indoor falloff coeff **9** (outdoor 10); door/wall loss **20 dB**; air loss **0.015 dB/m**.
- Cull calibration: a **30 dB** sound is heard to **~2.2 m**, `range = pow(2,(vol-30)/7) * 2.2` ("loudness doubles every 7 dB"). A 50 dB footstep → ~15 m. Use as the sound-radius cheap-reject before computing audibility.
- `psychLoud = 1 + (loudness - threshold) * alertFactor`, clamped to `alertMax` (default **30**). Per-sound `alertFactor` lets a clang alert more than a footstep at equal dB.
- **Highest-wins per tick**: multiple sounds in one tick do not stack additively within the tick; only the loudest raises alert that tick (additive *across* ticks). Replicate this or rapid footsteps spike alert unrealistically.
- Distances already in meters — no inch conversion. `log16` in TDM is natural-log-then-/ln10 → just use `log10`.
- The "apparent origin = the doorway the sound leaked through" trick has no portal analog; **v1 uses the true origin** as the investigate position (acceptable).

### Tests
- Same room, 3 m, 50 dB footstep → audibility well above 20 → heard, `alertUnits > 1`.
- Threshold edge: tune loudness so audibility lands just below 20 → not heard; +1 dB → heard (locks the `>` compare).
- Distance falloff monotonic across a distance table.
- Cull sanity: a 30 dB sound at ~2.2 m is at/below threshold (numbers transferred correctly).
- Blocker penalty: identical geometry with vs without a `doorBlocker` on the ray → blocked case exactly `perWallLossDb` (20) quieter; can flip heard→not-heard.
- `alertMax` clamp: a point-blank event yields `alertUnits == alertMax`, not more.
- Highest-wins-per-tick: two events one tick → alert rises by the louder only.
- Determinism.

## SLICE 5 — Graded alert FSM (Observant / Suspicious / Searching + decay + hysteresis)

**Why.** Today behavior is a binary radius flip. TDM's graded ladder — one float crossing named thresholds, with linear per-band decay, a dead-time before decay, and an up-hysteresis grace window — is what makes guards *feel* like they notice, investigate, and calm down. This is the spine that consumes slices 1–4.

**What.** One scalar `alertLevel` on the actor; a derived index mapped to `AiBehaviorKind`; pure functions to raise (from perception/sound), decay, and re-derive behavior. **Collapse TDM's entire `State` class hierarchy into free functions** — no subclasses (DOD law).

### iggy3d structs touched
- `AiBehaviorKind` (`AiState.hpp:13`): **insert** `Observant`, `Suspicious`, `Searching` between `Idle` and `Chasing` (keep existing `Alert` as the agitated/weapon-ready rung, or rename — document the mapping). Update `aiBehaviorKindName`.
- `AiActorState`: add
  ```cpp
  float        alertLevel = 0.0F;
  std::uint64_t lastRiseTick = 0;
  std::uint8_t maxAlertIndexThisEngagement = 0;
  std::uint64_t graceUntilTick = 0;
  float        graceThreshold = 0.0F;
  std::uint32_t graceCount = 0;
  ```
- New `AlertProfile` struct (referenced by `behaviorProfileId`), **normalized 0..1**, all named data:
  ```cpp
  float observantNorm, suspiciousNorm, searchingNorm, agitatedNorm, combatNorm; // boundaries
  std::uint32_t drainTicks[4];     // per-band decay durations
  std::uint32_t deadTimeTicks;     // hold flat after a rise
  float graceFrac; std::uint32_t graceWindowTicks; std::uint32_t graceCountLimit;
  ```
- Free functions:
  - `AiBehaviorKind alertIndexForLevel(float level, const AlertProfile&)` — the if/else-if ladder.
  - `void npcDecayAlert(AiActorState&, const AlertProfile&, uint64_t tick)` — dead-time gate + linear per-band decay.
  - `void npcRaiseAlert(AiActorState&, const AlertProfile&, float increment, uint64_t tick, bool hasValidTarget)` — clamp, recompute index, **no-target→cap-below-combat** rule, `lastRiseTick`, grace-window swallow on rises.
  - `void npcStepAlertBehavior(AiActorState&, const NpcPerceptionResult&, const SoundPerceptionResult&, const AlertProfile&, uint64_t tick)` — convert perception into an increment (or decay if nothing perceived) and re-derive behavior.

### Decay & rise (tick math, not milliseconds — iggy3d is tick-based)
- Each tick, if `tick >= lastRiseTick + deadTimeTicks` and `alertLevel > 0`: `alertLevel -= ratePerTick`, where `ratePerTick = (upperNorm - lowerNorm) / drainTicks[band]`. **Linear**, per-band.
- Rise: perception feeds an increment proportional to `(1 - distance/effectiveRadius)` (or sound's `alertUnits`). On a rise crossing a band boundary, set `lastRiseTick = tick` and open a grace window.
- **Drop TDM's `atime` random fuzzyness** or seed it from `deterministicPolicy` — headless tests must be byte-reproducible.

### Reference thresholds (TDM → normalized by combat=23)
- Raw: `thresh_1..5 = 1.5 / 6 / 10 / 18 / 23`. Normalized: observant `0.065`, suspicious `0.26`, searching `0.43`, agitated `0.78`, combat `1.0`. **Searching at ~0.43 is the investigate gate.**
- Band drains from `atime1..4 = 5 / 8 / 25 / 65 s` × tick rate. Dead-time `300 ms` → `ceil(0.3 * tickRate)`. Idle drift `0.01/s`, AlertIdle `0.005/s`.
- Grace: window `2/2/3/2 s`, frac `1.2/1.2/1.0/1.0`, count `5/5/4/4`.
- **Rules to replicate exactly:**
  - Combat requires a live enemy: `level >= combat` with `target == None` → pin to `Searching`/agitated and clamp just below combat (you can't fight an unnamed threat).
  - `alertIndex` is **always derived**, never set directly — single source of truth is the float.
  - **LOS-confirmed sightings bypass the grace gate** (`AI_VISALERT`): a direct visual on the target always punches through anti-spam; only ambient/sound stimuli are throttled.
  - Dead-time resets on every rise — continuous stimulus prevents decay (intended).
  - High-water mark `maxAlertIndexThisEngagement` chooses heightened-idle vs plain idle on the way down.

### Tests (`tests/npc_alert_fsm_tests.cpp`)
- `alertIndexForLevel` returns the right `AiBehaviorKind` just below/at/just above each boundary, including the combat clamp at 1.0.
- No-target rule: raising to combat with `target == None` pins to Searching/agitated, caps below combat, never Chasing/Attacking.
- Linear decay: from a fixed level with no perception, after exactly `drainTicks[band]` ticks the level falls one full band; dead-time holds flat for `deadTimeTicks` after a rise.
- Up-hysteresis: a burst of small same-source increments inside the grace window is swallowed up to `graceCountLimit`, then the next breaks through; a LOS-confirmed sighting bypasses grace.
- Round-trip ladder: scripted perceived→unperceived sequence walks Idle→Observant→Suspicious→Searching→Chasing→Attacking up and the reverse down, one rung per crossing, deterministically.
- Determinism / headless: full sequence runs on integer ticks only, fuzzyness dropped or seeded → byte-reproducible trace.

## SLICE 6 — Patrol + investigate-last-known-position memory

**Why.** The payoff arc: a guard patrols a route, spots the player, chases, **loses sight, blind-chases the last-known spot for ~3 s, gives up, investigates that spot, then returns home and calms down.** This is what makes the system read as "stealth AI" rather than "aggro radius."

**What.** A patrol waypoint ring + a small `AiMemory` blob + blind-chase/give-up logic, all in free functions extending `chooseNpcBehaviorIntent`/`buildNpcBehaviorCommand` (never replacing them). Ships as **two sub-slices** (6A patrol, 6B memory) so each is independently testable.

### iggy3d structs touched
- `AiActorState`: add `std::uint32_t patrolIndex = 0;` and `AiMemory memory;`.
- New plain struct:
  ```cpp
  struct AiMemory {
    Vec3 lastKnownTargetPos; std::uint64_t lastSeenTick = 0; bool hasLastKnown = false;
    Vec3 investigatePos;     bool hasInvestigatePos = false;
  };
  ```
  Use an explicit `bool hasInvestigatePos`, **not** a magic `INFINITY` sentinel (TDM uses `idVec3(INF,…)`; plain structs should never carry NaN/inf).
- `NpcBehaviorConfig`: add
  ```cpp
  std::vector<Vec3> patrolWaypoints;
  float waypointArriveRadiusMeters = 0.5F;
  std::uint32_t blindChaseTicks = 180;      // ~3 s at 60 Hz (MAX_BLIND_CHASE_TIME)
  std::uint32_t investigateWaitTicks = 120; // ~2 s (INVESTIGATE_SPOT_TIME_REMOTE)
  // reuse chaseStopDistanceMeters as the investigate arrive radius
  ```
- Free functions: `advancePatrolIndex(state, perception, config)`, `updateAiMemory(memory, perception, currentTick)`. Both pure.

### Behavior wiring
- **6A Patrol:** when no perceived target and Idle with a non-empty route → emit `Idle` + `MoveTowardTarget` toward `patrolWaypoints[patrolIndex]`; advance+wrap `patrolIndex` when `distance(actorPos, waypoint) < waypointArriveRadiusMeters`. `buildNpcBehaviorCommand` reuses the existing move command with the waypoint as destination. Preserve `patrolIndex` across interrupts so patrol resumes after give-up.
- **6B Memory + blind-chase/give-up:** `updateAiMemory` records `lastKnownTargetPos`/`lastSeenTick` whenever the target is perceived (`targetVisible`). While Chasing and the target is **not** currently perceived, keep moving toward `lastKnownTargetPos` (blind chase). When `currentTick - lastSeenTick > blindChaseTicks` **OR** the actor has reached `lastKnownTargetPos`, set `investigatePos = lastKnownTargetPos`, transition to Searching, `MoveTowardTarget` toward it, then `Wait` via `cooldownTicksRemaining = investigateWaitTicks`; on wait-expiry clear `hasInvestigatePos` and, if still no target, transition to `Returning` (`ReturnToAnchor` toward `homePosition` — already in `AiActorState`).

### Reference thresholds
- `MAX_BLIND_CHASE_TIME = 3000 ms` (hard cap 2× = 6000 ms); investigate stop-dist `64 u`, min-dist `20 u`, dwell `2000/300/2500 ms` (remote/standard/close). **Two exit conditions** for blind chase: reached last-known OR timeout — model both.
- Collapse TDM's two last-known positions (`lastVisibleEnemyPos` vs `lastVisibleReachableEnemyPos`) into one `lastKnownTargetPos` — iggy3d has AABB nav, no AAS reachability, so the distinction has no meaning yet.
- The SearchManager hiding-spot **tree is deferred** — v1 investigates a single `investigatePos`; multi-spot search is a later slice.

### Tests
- Patrol loop: 3 waypoints, no target → `patrolIndex` 0→1→2→0 as position crosses each arrive radius; intent always `MoveTowardTarget` toward the current waypoint.
- Patrol interrupt: target enters radius mid-patrol → flips Idle→Chasing same tick; `patrolIndex` preserved so patrol resumes after return.
- Memory capture: a tick with `targetVisible` sets `lastKnownTargetPos == targetPosition`, `lastSeenTick == currentTick`.
- Blind chase: target leaves at tick T; for `< T+blindChaseTicks` intent stays toward `lastKnownTargetPos`; at `T+blindChaseTicks` → Searching with `investigatePos == lastKnownTargetPos`.

## 1. Ground truth — the ten load-bearing facts

1. **One event pump.** `SdlWindow::pollEvents()` (SdlWindow.cpp:144-213) is the only `SDL_PollEvent` loop in the repo; unhandled events (key-up, non-left button-down, button-up, drop) are silently discarded. Editor input is otherwise **polled** (`SDL_GetKeyboardState` EditorFrame.cpp:443, `SDL_GetMouseState`, `SDL_GetRelativeMouseState` EditorFrame.cpp:512).
2. **Dynamic rendering only, one block per frame.** begin/end at CommandRecording.cpp 326/330 (empty), 515/689 (first-room), 878/933 (proxy). ImGui insertion = after the last HUD draw, before `cmdEndRendering`: **:329-330, :688-689, :932-933**.
3. **Capture copies the composited swapchain image** after `cmdEndRendering` (CommandRecording.cpp:691-733) into FrameCapture; artifacts are pixel-hash-sensitive. Anything drawn in the block lands in the PNG. Capture-enabled only on the two first-room paths (RenderLoop.cpp:538-544, 624-630).
4. **Two swapchain recreate paths.** App-driven `VulkanBackend::resize` (VulkanBackend.cpp:497-560; rebuilds ALL packet7 modules + FrameCapture + a fresh `RenderLoopCreateInfo` — a hook stored there is silently dropped unless re-supplied at **both** build sites :451-466 and :538-553) and in-frame recreate (RenderLoop.cpp:394-407) that notifies nobody. `SwapchainInfo.generation` (Swapchain.cpp:418) is the change signal; requested minImageCount is currently discarded (chooseImageCount Swapchain.cpp:107-113) and must be retained for `ImGui_ImplVulkan_SetMinImageCount`.
5. **`frame.viewport` is dual-purpose**: projection input AND swapchain-sizing truth (RenderLoop.cpp:394-398), with validation pinning `aspectRatio == width/height ± 0.001` (FrameInput.cpp:134-141). The content rect must be a **new field**; viewport stays swapchain-sized.
6. **Three coordinate spaces already exist**: logical window coords (SDL events/`SDL_GetMouseState`), drawable pixels (HiDPI ~2× on macOS; converted only by `resolveCreativeDrawablePointer`, UiInput.cpp:61-91), and now the content rect. ImGui works in logical coords with `DisplayFramebufferScale`; every conversion must be one shared helper or picking skews by 2×.
7. **Pointer lock is a distributed baseline**: captured at startup (main.cpp:233-235) and re-asserted by **15 call sites across 6 files** on modal close (EditorCatalog.cpp:351, EditorControls.cpp:418, EditorToolOptionsPanel.cpp:583, EditorTransformFrame.cpp:175, EditorAssetLibraryFrame.cpp:162/206/245-260, main.cpp:290/303/363/378). Desktop mode inverts the resting state; every site must consult the new owner or closing any panel silently re-grabs the pointer. `setTextInputActive` has **8** analogous sites that will fight ImGui's own `SDL_StartTextInput` calls: EditorControls.cpp:417, EditorCatalog.cpp:348, EditorToolOptionsPanel.cpp:582, EditorTransformFrame.cpp:174, EditorAssetLibraryFrame.cpp:161/205, main.cpp:362/377.
8. **The router routes exactly one context per frame** (InputRouter.cpp:495); `resolveInputContext` (EditorFrame.cpp:239-274) is an ordered first-active-wins list with `Capture` first (zero bindings ⇒ capture runs are input-inert). Esc is already bound (ToggleControls in EditorViewport, InputDefaults.cpp:722; CancelActiveTool elsewhere). `CreativeInputRouterState.bindingActive` is indexed by binding position — **append** bindings, never reorder.
9. **Mutation discipline exists and must be reused**: `Facade` (Facade.hpp:194) + `beginEditTransaction`/`completeEditTransaction` (EditorEdits.cpp:91-135) + receipt-returning kernels + whole-document snapshot history (depth 32, per-snapshot `source` labels, History.hpp:35-39). The isolated authored-asset edit session already runs a **second full `CreativeAppState`** behind `activeCreativeEditorAppState` (EditorAssetLibrary.cpp:604-614) — that seam IS the document-tab mechanism.
10. **Build/test shape**: `iggy3d` (engine lib, PUBLIC src/ include, warnings applied) ← `iggy3d_creative_app` (STATIC, all Editor*.cpp, PUBLIC include apps/iggy3d_creative) ← `i3dc` (main.cpp only). App-linked tests copy the `creative_authored_asset_tests` block (iggy3d_tests.cmake:306-315). `iggy3d_add_unit_test` links `iggy3d` only — insufficient for Editor* symbols. Test files must exist at configure time (FATAL_ERROR otherwise).

## 2. Decisions (locked unless recon proves them wrong)

- **DD-1 · Pin.** Vendor tag **`v1.92.8-docking`**, commit **`b61e56346a92cfcaf1f43a545ca37b0b32239654`** (verified live 2026-07-14; annotated tag — pin the commit SHA in the README, cgltf/stb precedent). Files: imgui.h/.cpp, imgui_internal.h, imgui_draw/tables/widgets.cpp, imconfig.h, imstb_*.h, LICENSE.txt, backends/imgui_impl_sdl3.{h,cpp}, backends/imgui_impl_vulkan.{h,cpp}. **No imgui_demo.cpp** (nothing may call ShowDemoWindow in committed code).
- **DD-2 · 1.92-series API realities** (integration code must match, older samples will not compile): `ImGui_ImplVulkan_Init(&info)` single-arg; dynamic-rendering config is `info.UseDynamicRendering = true` **plus nested `info.PipelineInfoMain.PipelineRenderingCreateInfo`** (sType `VK_STRUCTURE_TYPE_PIPELINE_RENDERING_CREATE_INFO_KHR`, colorAttachmentCount=1, format = `swapchain_.info().colorFormat` — runtime-chosen, Swapchain.cpp:59-74, never hardcode BGRA8); `info.ApiVersion = VK_API_VERSION_1_3`; `info.Queue`/`QueueFamily` = the graphics queue (`bootstrap_.queues()`); **`info.DescriptorPoolSize = 16`** and leave `DescriptorPool` null (backend creates its own pool — simplest correct option); `MinImageCount` from the retained requested count (K-8) and **`info.ImageCount = swapchain_.info().imageCount`** (assert ≥ MinImageCount ≥ 2 — this sizes the backend's per-frame buffer ring, covering frameSlotCount=2); **no** `ImGui_ImplVulkan_CreateFontsTexture` (1.92 dynamic-texture system, `IMGUI_HAS_TEXTURES`); **no** `IMGUI_IMPL_VULKAN_NO_PROTOTYPES` / `LoadFunctions` (the loader `Vulkan::Vulkan` is linked with prototypes, cmake/iggy3d_vulkan_deps.cmake:58-62). **Dockspace config:** the host window uses `ImGuiWindowFlags_NoBackground` + `ImGuiDockNodeFlags_PassthruCentralNode` so the central node stays transparent over the swapchain-rendered scene (there is no offscreen scene target — an opaque central node would paint over the entire viewport) and mouse input over it passes through to the app. Consequence: `io.WantCaptureMouse` is false over the central node — DD-8's activation condition depends on this and is pinned in `creative_viewport_layout_tests`.
- **DD-3 · Bridge ownership & frame protocol.** `DearImGuiVulkanBridge` is a **private member of `VulkanBackend`** wired exactly like `frameCapture_` (init at tail of `initializePacket5Modules` VulkanBackend.cpp:449-470; per-resize refresh in `resize` :536-554; shutdown between `waitIdle()` and `commandRecording_.destroy()` :670-672 — ImplVulkan_Shutdown → ImplSDL3_Shutdown → `ImGui::DestroyContext`, all after waitIdle). No public Vulkan-handle accessors are added. `VulkanBackendCreateInfo` gains two fields: **`void* nativeWindow`** (the `SDL_Window*`, from `window.nativeWindow()` at the `createCreativeRenderer` call site, EditorBootstrap.cpp:242-272 — the bridge needs it for `ImGui_ImplSDL3_InitForVulkan`; only the bridge .cpp casts it) and **`bool enableExternalUi`** (= `capturePath.empty()`, DL-1's construction gate: when false, no ImGui context is ever created and every method below no-ops). The app talks to the bridge through **3 narrow `VulkanBackend` methods**: `forwardExternalUiEvent(const SDL_Event&)` (→ `ImGui_ImplSDL3_ProcessEvent`; this is the work order's "event forwarding" home — main.cpp's SdlWindow hook body is a one-line cast-and-call with zero ImGui includes), `beginExternalUiFrame()` (ImplVulkan/ImplSDL3 NewFrame; returns false when disabled — the app skips all panel building on false), and `externalUiFrameActive()`. **`ImGui::Render()` is called by the app** in `endCreativeEditorDesktopFrame()` (EditorDesktopUi.cpp) after all panel building and command dispatch, immediately before `submitCreativeEditorFrame` (main.cpp:548) — **never inside the record hook** (a skipped submit — SkipFrame/NotDrawable, RenderLoop.cpp:386-392/:437-449 — must still leave the frame Rendered or the next NewFrame trips ImGui's assert). **Recreate handling:** the bridge caches `swapchain generation + colorFormat`; the *record hook* (which sees post-recreate swapchain state, covering the in-frame recreate at RenderLoop.cpp:394-407) compares them — on generation change with same format → `ImGui_ImplVulkan_SetMinImageCount` + ImageCount re-check at next begin-frame; on **colorFormat change** the hook skips recording (returns false — one deliberate UI-less frame) and flags a rebuild that the next `beginExternalUiFrame()` performs via waitIdle + ImplVulkan Shutdown/Init (SetMinImageCount alone cannot fix a format mismatch). Init is idempotent (resize can re-run `initializePacket5Modules` from NotDrawable).
- **DD-4 · Hook shape.** `ExternalUiRecordHook { bool (*record)(void* user, VkCommandBuffer cb, VkExtent2D extent, uint32_t frameSlot); void* user; }` in the new header, nullable field on all three record-info structs, forwarded from the 4 populate sites in RenderLoop, installed via `RenderLoopCreateInfo` **at both build sites** (fact 4). The bridge's record function returns false (no-op) when disabled, when no frame is active, or when `ImGui::GetDrawData()` is null/empty. New receipt field **`external_ui_recorded = (hook != null && hook returned true)`** — additive; existing receipt keys untouched (smokes assert them); the same fact is appended to the capture `.meta.kv` (FrameCapture.cpp:409 write site) so T-0 can assert it from artifacts. `VulkanBackend`/`FrameInput` signatures remain pinned by the focused Vulkan smoke targets.
- **DD-5 · Content rect.** New `RenderContentViewport { int32 x, y; uint32 width, height; }` in FrameInput.hpp + `FrameInput.contentViewport` field, in **drawable-pixel space**, default = full swapchain extent. `validateFrameInput` gains a clamp/never-zero branch (new reason codes; existing enumerators untouched — render_projection_input_tests pins them). `frame.viewport` and `viewport.aspectRatio` stay swapchain-truth (fact 5); only `clipFromView` switches to content aspect. Under `--capture` and whenever the desktop shell is off, contentViewport ≡ full extent, so every proof log and hash is byte-identical.
- **DD-6 · Scissor rule.** Scene draws get content-rect viewport/scissor at the three `vkCmdSetViewport/Scissor` sites (CommandRecording.cpp:315-325, :503-513, :866-876); viewport/scissor are **re-set to full extent immediately before the UI hook**; `renderingInfo.renderArea` stays full extent always (legacy HUD is `vkCmdClearAttachments` — rects outside renderArea are validation errors).
- **DD-7 · Dispatcher.** `EditorDesktopCommands.cpp` owns `CreativeDesktopCommandId` (new enum, fixed-capacity frame `CreativeDesktopCommandFrame` — own type, NOT `CreativeEditorToolOptionsCommandList` whose capacity is 14 < its own enum) and is the **sole** consumer. It does not reimplement kernels: menu/panel commands map 1:1 onto the existing bodies in EditorCommandInput.cpp (New:305 / Save:297 / Load:311 / Undo:223 / Redo:226 / Delete:202 / Duplicate:252 — **including the mandatory post-steps**: `clearEditHistory`, `resetCreativeEditorForDocumentReplacement`, gesture finalization) and onto `activateCreativeEditorObjectAction` for tool/asset commands. Every entry resolves `activeCreativeEditorAppState(editor, appState)` first (asset-edit sessions must not corrupt the map). Dispatch happens at the existing slot beside main.cpp:422-429, gated by the same `modalBlocksWorldActions` contract (main.cpp:401-412, incl. `finalizeCreativeEditorContinuousGestures`).
- **DD-8 · Input arbitration.** New `CreativeInputContext::DesktopUi` appended before `Count` (InputRouter.hpp:28) + toString case + candidate in `resolveInputContext` **after Capture** (EditorFrame.cpp:247-267) + exhaustive-switch updates (EditorCatalog.cpp:317-338, EditorActionHints.cpp:518-560). Activation condition = `io.WantCaptureKeyboard || io.WantCaptureMouse` while the viewport does not own the pointer. Because editor keys are *polled*, event filtering alone cannot honor WantCaptureKeyboard — the polled sample is gated at the existing choke point (`enabled = …` pattern, EditorFrame.cpp:486-489). DesktopUi is excluded from `admitCreativeEditorNavigation`'s viewport list (EditorFrame.cpp:413-417) ⇒ fly camera off while UI focused. ImGui controller navigation stays OFF; the gamepad path (polled, EditorGamepad.cpp:68) is untouched.
- **DD-9 · Pointer ownership.** One owner: `DesktopPointerPolicy` in EditorDesktopUi (states: `FreePointer` ↔ `ViewportCaptured`). Baseline flips to free in desktop mode (main.cpp:233-235); click in the central viewport → `ViewportCaptured` (relative mouse on), **Esc** releases. **Esc collision resolved WITHOUT touching the binding table**: the default table stays as-is (a second Press-activation Esc binding in EditorViewport would be recorded by `auditCreativeInputBindings` — InputRouter.cpp:549-579 — and **three suites pin `conflictCount == 0`**: creative_interaction_tests.cpp:856-879, creative_catalog_tests.cpp:630/644, creative_control_profile_tests.cpp:73-74). ## 3. Laws

- **DL-1 (Capture invariance).** Under `--capture`: the desktop shell is **never constructed** (bootstrap-time gate on the existing `!capturePath.empty()` bool, main.cpp:238 — a hard construction gate, not a context check); contentViewport ≡ full extent; legacy overlay building (main.cpp:533-546) untouched. Acceptance for every slice: capture artifacts byte-identical (see T-0).
- **DL-2 (No ImGui types leak).** `imgui.h` may be included only by: `DearImGuiVulkanBridge.*`, `EditorDesktopUi.cpp`/`EditorDesktopPanels.cpp`/`EditorDesktopCommands.cpp` internals. Never in FrameInput.hpp, RenderLoop.hpp, CommandRecording.hpp, InputRouter.hpp, EditorState.hpp, SdlWindow.hpp, or any generic header. `ExternalUiRecordHook.hpp` is plain function-pointer C++ with zero ImGui includes. `SdlWindow`'s event hook forwards `const SDL_Event&` — SDL types are already its vocabulary.
  FM-001 adds `apps/first_move/FirstMoveUi.cpp` as the application-private ImGui
  consumer for the user-requested native Hunt game. Its public header and
  `main.cpp` expose no ImGui types. It uses the existing bridge and does not
  change Creative's capture-time exclusion of the desktop UI.
  FM001-R1 permits `tests/unit/first_move_input_tests.cpp` to privately include
  `imgui.h` and `imgui_internal.h` for an in-memory regression of complete
  explanation visibility. This single test translation unit may privately link
  `iggy3d_imgui`; no ImGui type is added to a public header or model contract.
- **DL-3 (Widget purity).** Panel code reads projection structs and writes command IDs into the bounded frame. No calls to Facade/History/Document/window from widget code; the dispatcher is the only mutation site. (Existing panels violate this — they are not being retrofitted in this batch, but no NEW code may.)
- **DL-4 (Kernel reuse).** Any mutation reachable from the UI must run through the existing transaction pattern (`beginEditTransaction` → kernel receipt → `completeEditTransaction`). Missing kernels get added to the kernel layer with receipts (worklist §5), never inlined into panel or dispatcher code.
- **DL-5 (Spine gate).** Slices touching `SdlWindow`, `VulkanBackend`, `CommandRecording`, `RenderLoop`, `FrameSync` are **core-spine work** (docs/core_spine_work_rules.md): Gate-0 preflight, no new **first-party** submits/semaphores (single-submit plan stays, RenderLoop.cpp:683-696), receipts additive, smokes must stay green untouched (their `pollEvents()`/`resize()` call signatures are pinned — hooks are additive setters, never new parameters). **Known whitelisted exception:** the 1.92 ImGui Vulkan backend's dynamic-texture system submits its own one-off command buffer with a blocking wait on `InitInfo.Queue` from inside `RenderDrawData` (font atlas upload — first shell frame and on font changes). Same-thread on the graphics queue, safe here; expect the one-time mid-frame stall and do not misdiagnose it as a regression.
- **DL-6 (One conversion helper).** All logical↔drawable↔content-rect math lives in one pure, unit-tested helper family next to `resolveCreativeDrawablePointer` (UiInput.cpp) — the repo's proven testable-input pattern. No panel does its own DPI math.
- **DL-7 (Bindings append-only; SDL_GetRelativeMouseState single-consumer** — EditorFrame.cpp:512 remains the only reader; ImGui never needs it since relative mode implies UI-inactive.)
- **DL-8 (Vendored code stays third-party).** `iggy3d_imgui` target: no `iggy3d_apply_warnings`, `SYSTEM PUBLIC` includes, compiled without `-ffp-contract=off` concerns (UI code participates in no save/hash determinism). Do not edit vendored sources; `imconfig.h` is the only allowed customization point and stays upstream-default plus a comment header.
- **DL-9 (Untouchables).** The two dirty `.claude/worktrees/*` gitlinks are never staged. `~/iggy` prototype is reference-only. Never edit the stale InputRouter copies inside `.claude/worktrees/`.

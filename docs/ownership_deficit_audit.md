# Ownership Deficit Audit — the queue of "what else needs ownership"

## Ownership-deficit audit — "what else needs ownership" after `activeRoomCollision`

### 1. The pattern (exemplar = `activeRoomCollision`)

The pathology is **stored derived state with no owner**: a value that is *computed* from an input (a loaded room, an identity, a player pose), then **cached on the ~200-field `ProductAppWindowState` god-struct**, rebuilt at **many scattered writer sites**, and **read cross-frame by unrelated subsystems** — with **no revision/provenance token** that lets a reader detect it is stale. Correctness rests entirely on every writer *remembering by convention* to rebuild it (often in lockstep with a sibling, on adjacent lines) before the next reader touches it. The exemplar being fixed is `window.activeRoomCollision`: a `SpatialSurfaceSet` derived from `activeRoom.room` + live door state, rebuilt at ~15 sites from a ~12-writer input with no dirty guard, whose fix (`docs/active_room_collision_freshness_preflight_v0_2.md`, Gate-1 ratified 2026-07-07) is a single owned `ActiveRoomCollisionFreshnessStore` with **one `ensureActiveRoomCollisionFresh` verb** that stamps every bake with `{roomRevision, sessionHash}` and rebakes on demand iff either drifted. This audit finds the **next seams that need the same treatment**, ranked by `(staleness-risk × reader-count) / effort`.

### 2. Confirmed ownership deficits — ranked

The **5 pathology signals**: **[MW]** multiple independent writers · **[NT]** no freshness/revision token · **[TD]** timing-dependent (correctness depends on rebuild-before-read ordering) · **[CS]** copy-stomp exposure (whole-struct copy carries a stale value + its ad-hoc valid bit) · **[XR]** cross-frame readers assume it is current.

### 3. Checked and cleared — do not re-litigate

These were audited and are **NOT** the pathology — either **stateless-on-demand** (recomputed fresh every read, never trusted across frames) or **already funneled** (single owner / receipt-only reader / already carries a provenance token). Leave them alone unless the whole enclosing block is retired.

**Already carries a provenance token (the one that got it right):**
- `window.creativeBakedRoomStale*` (`+ StaleDocumentId + StaleRevision + Status + ReasonCode`) — **the model to copy.** Has `{documentId, revision}` provenance and a single record-pair owner. Crucially the **rebuild decision does not read it**: `InputFrame.cpp:1320` recomputes `creativeDocumentChanged` fresh from the revision snapshot each frame; the stale flag's only consumer is the receipt (`CreativeUiFields.cpp:451-459`). Stored telemetry, not load-bearing.

**Receipt / FramePresenter mirrors (recomputed-and-recopied every projection frame; only readers are receipt emitters):**
- `window.roomEditorOverlay / roomEditorHud / topDownMap / positionHud / physicsDebugHud / npcBehaviorDebugHud` — read only by `SaveStateFields.cpp:151-221`.
- `window.creativeUiProjection` — single writer, re-emitted by `ReceiptBuilder`, no logic reader.
- `window.mouseCapture.inputOwner` — 2 writers assigning the same freshly-derived `policy.inputOwner`; single receipt reader (`FrontendSettingsWindowFields.cpp:173`).
- gamepad mirror `window.gamepadAvailable / gamepadName / gamepadMapping` — one init-site writer, receipt-only reader; not derived-from-changing-input.
- `ProductGameplayProjectionFrame` (scene/debug/drawList/viewportFrame/renderBridge/HUDs) — rebuilt from scratch each projection frame; stateless-on-demand.

**Write-only caches — the pathology *structure* but no reader can be misled (delete the field, don't build a store):**
- `window.inputOwner + window.gameplayInputSuppressed` — **~22 sync-writer scatter, missing token, no production reader.** Every consumer re-derives via `resolveProductActiveSurface` (`InputFrame.cpp:170/307`, `FrontendRouter.cpp:346`, `ReceiptBuilder.cpp:32`). Harm surface absent → **delete the stored fields + 22 writers**, assert on `resolveProductActiveSurface` directly. If a reader is ever added, route it through that verb, not the cache.
- `window.runtimeStateHash` — scalar mirror of the always-recomputable `SessionState::stateHash()`, written at ~15 sites but read only by the receipt (`GameplayRuntimeMovementFields.cpp:27`) and a debug panel (`FramePresenter.cpp:919`). A stale value only mis-displays a debug hash. **On-demand simplification** (`read session.stateHash()` at the 2 sites, delete the field), not a Store.

**Stateless-on-demand / authoritative-not-derived (correctly excluded):**

- `SessionState.reasoningGraph`, `SessionState.outcomeTable`, `creativeApp.undoStack` — **authoritative** state (a graph, a table, a history stack) with a single owner + push/pop/clear API; not derived state that must be re-freshened against an input. `window.creativeUndo` readers are recomputed from the stack each frame.

Not a scattered-derived-data deficit.

### 4. Rollout — gated slices, ranked by risk × leverage

These are **not one refactor**. Each ships as a **gated slice like the collision guard** (`docs/active_room_collision_freshness_preflight_v0_2.md`): Gate-0 preflight → Gate-1 ratification → staged writer removal proving readers now depend on the freshness seam, with the pre-slice baseline diffable in tests. This is the **freshness-store discipline** generalized — *one owner ensures a derived truth is fresh before any reader consumes it* — the single-threaded on-ramp to what the future job system will make async. Fire order follows the ranking:

1. **`activeRoom` (#1, score 9.0)** — do **inside** the collision slice's later gates (G4/G5 removal), not as a separate effort: absorb `{activeRoom, activeRoomCollision, revision}` into the one `ActiveRoomCollisionFreshnessStore`, killing the window↔roomEditing duplicate at the same time. Highest leverage, lowest marginal cost.
2. **`activeCreative` mirror (#2, score 4.0)** — smallest self-contained slice (**S**): migrate the FrontendRouter + `SaveStateFields` readers onto `creativeApp.identity`, fix the `Flow.cpp:78-79` independent writer, delete `window.activeCreative`. **Re-issue finding #10 with the corrected writer count (2, not funnel-only).**
3. **`creativeFlyAnchor` (#3, score 3.0)** — its own new `CreativeFlyAnchor` store + `ensureFreshAnchor(session)`; the exemplar shape one level smaller, [CS] latent so no acute deadline.

Reread this to pick the next seam: **absorb #1 into the collision fix now; #2 is the cheapest standalone win; #3 waits for its own preflight.**

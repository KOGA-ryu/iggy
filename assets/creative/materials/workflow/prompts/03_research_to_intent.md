# Prompt 03: Translate Research into Material Intent

This prompt creates the complete causal specification before the main
implementation.

## Required reading

- package `WORKSTREAM.md`;
- `workflow/02_material_intent/AGENTS.md`;
- `workflow/TEXTURE_WORKBENCH.md`;
- newly updated source ledger;
- package profile, `RESEARCH_INTENT.md`, and focused tests.

## Build the intent ledger

For every major research finding, write:

- Observation;
- Intent;
- Implementation;
- Not justified.

Update `RESEARCH_INTENT.md` so the material can be reviewed without reading the
generator.

## Define material anatomy

Fill the dossier layer table with:

- physical meaning;
- scale and amplitude;
- orientation;
- element identity;
- generated outputs;
- absence or rest rule;
- isolated proof.

Separate:

- construction;
- macro;
- medium;
- edge and event;
- micro;
- stylization;
- optional contextual overlays.

Write the same contract into `workflow_contract.layer_provenance`. Each entry
must contain `id`, `physical_meaning`, `sources`, `outputs`, `consumers`,
`proof_ids`, `rest_rule`, and `claim_ids`. The prose and machine-readable
versions must agree.

For new or materially revised hero/reusable work, add
`workflow_contract.surface_method_contract`. Write the exact effect order,
composition operation, masks, coordinate frame, geometry-to-map transfer,
damage placement state, consumers, and proofs. Translate legacy gloss,
blend-mode, anchor-point, sculpt, or bake terminology into the current
Blender/engine contract.

## Define color

Specify:

- accepted base families;
- multiple related shades inside one element;
- broad warm and cool passages;
- anatomy- or construction-driven colors;
- event colors;
- ink and highlight colors;
- prohibited saturation, photographed light, AO, and generic grime.

Write the cumulative color order. Do not leave color as "choose a brown" or
"add variation".

## Define PBR

Write independent contracts for:

- height in metres;
- normal contributions and combination;
- broad and local roughness behavior;
- real AO only;
- physical metalness layers;
- opacity when appropriate;
- distance hierarchy.

State which research authorizes each relief amplitude. Default unsupported
depth to zero.

## Define coordinates and semantics

Specify:

- coordinate origin and axes;
- metre repeat or accumulated length;
- behavior under resize and deformation;
- element identities;
- phase and variant;
- end, cut, fracture, trim, or repair face identity;
- Boolean-safe attribute assignment;
- Blender reconstruction;
- target-engine reconstruction.

## Define authored vocabulary

List the finite patterns or motifs needed:

- unique source shapes;
- reusable quarters or mirrored portions;
- allowed transforms;
- forbidden transforms;
- family counts;
- quiet variants;
- champion seed.

Do not say "procedurally generate variations" without defining what is varied
and what must remain invariant.

## Resolve the workbench strategy set

For every major component, update the dossier with:

- relevant shared tools already on the bench;
- package-specific donors and their exact reusable boundary;
- rejected donors and the observed failure;
- missing tool dependencies;
- at least two technically viable strategies;
- selection evidence: static ownership review, measurement, cheap comparison
  board, performance constraint, engine parity, or actual-consumer proof.

Do not select a strategy because its code is nearest or already open. Compare
how each route owns scale, coordinates, composition, repetition, quiet areas,
consumer semantics, and engine translation.

When the research clearly eliminates a strategy, preserve the rejected reason
and narrow to one production route. When a visual ambiguity remains, carry
2–4 semantic parameter or strategy records into Prompt 04's cheap candidate
gate. Do not duplicate a complete graph for each option.

## Define acceptance

Write:

- first red observable;
- focused contract tests;
- required proof views;
- professional comparison targets;
- exact conditions for rejection;
- manual acceptance requirement;
- target-engine parity status.

Add or update tests for the profile and intent contract before the main
implementation when practical.

## Dossier update

Complete:

- material anatomy and layer contract;
- coordinate and semantic contract;
- color contract;
- PBR contract;
- damage and overlay boundary;
- implementation ledger;
- expected verification.
- at-hand tool/donor inventory;
- multi-strategy decisions and unresolved candidate records.

Set Stage 03 to `complete` only when no major visible behavior remains described
as generic noise, variation, detail, or stylization.

## Exit gate

Do not advance unless:

- every visible band has meaning, scale, orientation, and proof;
- within-element color layering is explicit;
- PBR outputs have different causal rules;
- stable coordinates and semantic attributes are specified;
- finite pattern vocabulary exists;
- every major component has selected or retained multiple strategies with
  explicit decision evidence;
- missing reusable tools are scheduled before the dependent component;
- unsupported features are zero or excluded;
- the first repair and focused gates are concrete.

Then execute `04_coded_implementation_blueprint.md`.

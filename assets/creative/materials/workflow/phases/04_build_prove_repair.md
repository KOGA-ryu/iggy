## Fast loop

Do not regenerate the complete final proof package after every small change.

Build the selected champion one accepted component at a time:

1. substrate or physical material identity;
2. macro value organization;
3. medium construction or manufacturing structure;
4. geometry or material-event response;
5. microstructure;
6. restrained stylization;
7. optional damage or condition only when separately authorized.

For each component, execute the already reviewed code, render its isolated
proof and cumulative proof, compare against its named source observations,
record its repair count, and accept or repair it before assembly. Do not add a
later component to hide a failed earlier one.

Within a component build or repair, use:

1. syntax and profile validation;
2. the smallest red/green unit gate;
3. a no-proof or one-proof build in a temporary output directory;
4. one changed diagnostic view;
5. the full proof package only at a milestone or final candidate.

Execute the ordered surface-method contract without flattening its masks,
directional transforms, or geometry-to-map boundary.

Canonical output may only be written by a complete build. Fast or targeted
builds must use an explicit temporary output directory.

Recommended builder interface:

```text
--proof-set none
--proof-set changed --proof <proof-id>
--proof-set all
```

`none` and `changed` must reject the canonical output path.

Final-resolution generation, documentation synchronization, saved-file checks,
and the complete proof package happen only for the selected champion or a
newly accepted reusable component. They do not run for discarded exploratory
candidates.

## Automatic audits

Before the full final build, run `audit_material_package.py`. It rejects:

- unexpected files in canonical output;
- unlinked texture image nodes;
- shader Attribute nodes with no outgoing route;
- geometry attributes that are neither consumed nor declared storage-only;
- numeric claims without measured, proxy, authored, or inherited authority;
- performance-budget overruns;
- stale synchronized coded demands;
- `accepted` status without the tier’s required actual-target proof.

## Repair economy

Critique the entire failed render before editing. Record one ledger covering
macro value, construction read, material response, repetition, symbols or
pareidolia, feature hierarchy, distance read, and host integration. Identify
the highest causal component, then bundle all related corrections that share
that owner into one reviewed repair blueprint.

This is not permission to cross ownership boundaries. A failed close normal
proof does not authorize geometry redesign; a failed silhouette proof does not
authorize grunge. It prevents an expensive full-build cycle for every
individual symptom of the same causal defect.

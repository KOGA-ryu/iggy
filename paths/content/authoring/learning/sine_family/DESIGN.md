# Sine equations: a reusable teaching family

This is the editable `sine_turn_v1` example for the common recipe command.
It reuses the reviewed Wave 01 sine lesson, six-role question template and
original cases. The two Markdown templates start byte for byte from that
published source. The shared runner supplies packaging and checks; the frozen
mathematical module supplies exact certificates. Writers edit four data/prose
files and do not copy or modify Python.

From the Paths root:

```sh
python3 -B tools/author_question_family.py init content/authoring/drafts/sine_next --family sine_turn_v1 --package sine_next
python3 -B tools/author_question_family.py check content/authoring/drafts/sine_next
```

The destination must be new. Checking returns an unpublished candidate and an
immutable evidence path. Edit the recipe or Markdown and rerun to rebuild it;
no C++ build is needed. The ordinary exporter handles coordinator publication.

## Learning claim and prerequisites

These questions ask learners to isolate a sine coordinate, find the other
permitted angle, choose a useful algebraic move, explain a reflection, repair
the first interval error and select a complete solution set. Prerequisites are
signed arithmetic, equality, radians, interval inequalities and unit-circle
coordinates. The lesson defines the symbols and explains each operation,
its inverse and its check. Success measures the requested symbolic choices
with available reading and corrections. It does not establish unaided proof,
retention, general inverse-trigonometric fluency or measured transfer. The six
roles are exercise purposes, not six support levels.

## Numerical contract and editable seeds

Keep `parameters.domain` exactly as supplied: real radian angles on
`0 <= theta < 2pi`. Lower and upper are coefficients of pi. Degree measures,
different endpoints, multi-turn intervals and arbitrary coordinates need a
different reviewed family.

Each of `sample`, `practice` and `fresh_check` has one named case for each of
the six roles. Each case has four fields:

| Field | Meaning and limits |
| --- | --- |
| level | Exact sine height as JSON text: `"-1"`, `"-1/2"`, `"0"`, `"1/2"` or `"1"`, subject to the role restrictions below |
| coefficient_sign | Integer `-1` or `1`; A has magnitude 2 at half heights and 1 at integer heights |
| offset | Integer B from -2 through 2 |
| known_branch | Zero-based index in the ascending permitted angle list; use 0 except when worked_check or explain_step supplies a known angle |

The producer constructs `C = A * level + B`, yielding the original
`A sin(theta) + B = C`. Certificates receive only A, B, C and the known angle;
they derive the height from the original equation. For example, changing the
sample read_notation case's offset from 0 to 1 changes `2 sin(theta) = 1` to
`2 sin(theta) + 1 = 2`; answers and feedback calculations follow automatically.
It changes that question's identity while preserving the other 17 originals.

| Role | Additional limits and teaching purpose |
| --- | --- |
| read_notation | Nonzero height, so the opposite-sign distractor is distinct |
| worked_check | Heights -1/2, 0 or 1/2, so there is a distinct second point |
| choose_next_step | At integer heights the sign must be -1, so subtracting B alone does not isolate sine with coefficient 1 |
| explain_step | Heights -1/2 or 1/2, preserving the reviewed nonzero reflection contrast |
| repair_error | Any permitted height; identify L2 before selecting the corrected set |
| independent | Any permitted height; all and only the interval solutions, with no supplied intermediate method |

Each set must use a different displayed original for the same role. The
reflection question displays alpha and its sine height; changing an undisplayed
offset alone cannot count as fresh practice. Invalid seeds identify their
recipe file and exact case field. This finite family contains no approximate
trigonometry or arbitrary-expression evaluator.

## Teaching, feedback and variation

The default three sets retain the reviewed progression: positive and negative
half heights, zero, extreme heights, a known angle from the second branch and
an excluded endpoint. Their six roles share one lesson and one question
template. Each role supplies title, objective and prerequisites in the recipe.

Each wrong choice keeps its own semantic ID and correction when the shared
runner changes display position. The repeated known angle is a valid solution
that misses the request for another angle. The partially isolated equation is
valid but misses the stated goal. Opposite heights fail substitution; an
omitted angle makes a set incomplete; 2pi violates the right endpoint. These
different reasons must remain explicit when editing feedback.

The separate worked example `2 sin(theta) + 2 = 4` cannot be generated by these
seeds. Its given alone is public; Hint, Answer and Solution are independently
closed. The proof explains the exact reference triangle, signs, reflection and
intersection count. Keep the standard block IDs start, terms, rule, condition,
worked, errors, practice and summary. The independent question has one uncued
decision. Routine prose QA belongs to the coordinator.

## Template fields

Shared fields are subject, subject_title, chapter, chapter_title, reading_id
and reading_title. Question fields use a role prefix, for example
`{{worked_check_other}}`. The runner supplies id, title, objective, given,
choices_1 and after_1; repair_error also has choices_2 and after_2.

The provider supplies these numeric/plain-math suffixes for every role:

- a, b, c, rhs, level, opposite, shifted;
- answers, count, known, other, omitted;
- wrong_angle, wrong_coordinate, reflected, reflected_raw, reflection_shift;
- halfturn, other_reflection, contrast, contrast_lhs;
- wrong_sign_lhs, shifted_lhs, endpoint_lhs.

Use the existing template as the placement reference. Angle fields use exact
plain text such as pi/6; givens, choices and reached working use the existing
LaTeX renderer. Prose lives in Markdown, not in provider code. Do not add a
hard-coded answer that stops following the numerical fields.

## Verification, identity and source

The canonical checker reuses Wave 01 exact rotations in Q(sqrt(3)), original
substitution and the unit-circle intersection count. Membership plus the count
proves completeness over real angles. The common pipeline compiles all 18
questions, compares every key and reached state with its certificate, replays
21 decisions and 42 wrong choices with saved work, and checks the three closed
worked disclosures. Targeted tests independently fold angles into reference
triangles across every permitted per-role seed and probe invalid edits.

IDs bind package, family version, set, role and original mathematical case.
Prose edits retain IDs but may change stamps. A new package creates new IDs;
using a new name alone does not create new mathematical practice. The supplied
examples duplicate reviewed Wave 01 mathematics and remain unpublished.

Source/tool/binary hashes and the exact four author inputs are retained in
each immutable check. The fixed registry also records the imported Wave 01
module and its local pilot import. Its old recipe reader and packaging code
are not called by this workflow. All published Wave 01–04 files remain frozen;
they are historical reproduction sources, not additional writer entry points.

The prior [Wave 01 review](../../production/wave01/trigonometry/DESIGN.md)
records the OpenStax references and original Paths authorship. No external
exercise wording was copied and no new web-source review is claimed here.
Visual appearance and learner outcomes remain unobserved. No window or
screenshot is required for these authoring checks.
